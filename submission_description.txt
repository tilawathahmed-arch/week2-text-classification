This report presents a practical strategy for designing and implementing a supervised text-classification pipeline using Natural Language Processing techniques. The project uses the Cornell Sentence Polarity Dataset v1.0, which contains 10,662 Rotten Tomatoes movie-review snippets divided equally into 5,331 positive and 5,331 negative examples. The task is formulated as binary sentiment classification, where the objective is to predict the sentiment label of an unseen text snippet.

The report explains the complete classification workflow, beginning with dataset loading, validation, and text preparation. It describes normalization steps such as lowercasing, whitespace cleanup, handling markup and URL/email patterns, and preserving meaningful words, contractions, and negation terms. It compares feature-extraction techniques including Bag of Words, CountVectorizer, TF-IDF, word unigrams and bigrams, character n-grams, and contextual embeddings. TF-IDF with unigram and bigram features is selected as the main representation for the initial classical machine-learning experiment.

The proposed model comparison includes Multinomial Naive Bayes, Logistic Regression, and Linear Support Vector Classification. A most-frequent-class dummy classifier is included as a simple reference baseline. The report outlines the model-training procedure, including a stratified 80/20 train-test split and stratified five-fold cross-validation on the training partition. Macro-F1 is used as the primary model-selection metric, with accuracy as a tie-breaker. The final test partition is reserved for one unbiased evaluation after model selection.

The evaluation framework covers accuracy, precision, recall, F1-score, macro-F1, weighted-F1, ROC-AUC where decision scores are available, classification reports, and confusion matrices. The report also discusses possible challenges such as label noise, short text context, negation, vocabulary sparsity, domain differences, and data leakage, along with practical mitigation methods.

A Python implementation script accompanies the report. It compares the candidate pipelines and exports cross-validation results, final test metrics, predictions, model feature weights, visualizations, and a saved model. The report distinguishes the implementation workflow from measured model performance: full-corpus classifier scores should be generated by running the script on the complete public dataset rather than inferred or assumed.
